# 경로 처리 과정 표시와 지도 위 후보 카드

기존 AI 검색은 최종 결과가 도착하기 전까지 요청 조건과 후보 비교 과정을 볼 수 없었고, 경로 카드는 검색 입력 영역 아래에 있었다. 이 변경은 실제 계산 진행과 조건별 근거를 왼쪽에 표시하고, 후보 카드를 지도 왼쪽 위의 반투명 세로 패널로 옮긴다.

## 포함 범위

- `POST /api/agent/query/stream`: Qwen 해석, 장소 확인, 실제 경로 작업 진행, 최종 결과를 NDJSON으로 전달한다.
- `rank_routes` 진행 콜백: 도로망 준비, 최단·맞춤 후보 생성, 시설 집계, 요청 조건별 비교를 완료 시점에 알린다. 기존 `/query`와 `/execute`의 추천 로직과 응답은 유지한다.
- 후보 주변 30m의 등록 가로등·방범 CCTV 위치를 PostGIS로 집계한다. 4326 경로를 5179로 변환해 `ST_DWithin`을 사용하고 동일 좌표를 중복 제거한다. 이 개수는 설명용이며 추천 점수·실제 조도·안전 확률과 구분한다.
- React가 스트림을 읽어 실제 진행 메시지를 표시한다. 같은 작업 ID의 메시지는 작업 중에서 완료로 갱신한다. 오류와 자료 부족은 완료처럼 표시하지 않는다.
- 질문 입력·검색 버튼을 고정하고 아래 처리 내용만 독립 스크롤한다.
- 지도 카드에 선택·상세 보기·숨기기/보이기를 제공한다. 숨긴 뒤에도 후보 막대는 남는다. 경로 자동 시점은 카드가 가리는 영역을 피하도록 맞춘다.

Qwen 모델, 자연어 해석 규칙, 경로 탐색 알고리즘, DB 데이터·스키마, 다른 지도 레이어는 변경하지 않는다. Jev 실험·관련 설정과 비밀키는 이 브랜치에 포함하지 않는다.

## 실행

기존 환경변수와 DB로 `docker compose up -d --build backend frontend`를 실행한다. 이번 기능용 DB 마이그레이션은 없다. Nginx의 스트림 주소는 `proxy_buffering off`로 중간 이벤트를 바로 전달한다.

## 확인 예시

> 밤 10시에 정부인천지방합동청사에서 두리하나어린이집까지 가로등과 CCTV가 많은 길로 안내해줘. 계단은 피하고 건널목은 적게 지나고 싶어

검증한 담당자 DB에서는 최단 약 746m·맞춤 약 878m, 경로 주변 등록 가로등 위치 29곳·60곳, 기록된 계단 구간 18m·0m, 건널목 5개·2개가 나왔다. 실제 입력·데이터에 따라 결과는 달라진다. CCTV 지표는 최단 후보가 더 높다고 그대로 설명하며, 추천 후보가 모든 조건에서 더 좋다고 주장하지 않는다.

## 검증

- 백엔드: `python -m pytest tests/unit`.
- 프런트: `node --experimental-strip-types --test src/*.test.ts`, `npm run build`.
- 스트림 실제 호출: 백엔드 평가 모듈 `python -m evals.route_progress_smoke`. 기본 주소는 같은 Compose 네트워크의 프런트 프록시이며 `--url`로 변경할 수 있다.
- 선택적 브라우저 검사: Playwright를 사용할 수 있고 Chrome이 설치된 테스트 환경에서 `node tests/floating-routes.e2e.cjs`. `E2E_BASE_URL`로 실행 주소를 지정할 수 있다. 주간·야간, 카드 선택, 독립 스크롤, 숨기기·다시 펼치기를 확인한다. 브라우저 테스트는 user_id를 null로 보내 테스트 추천·선택 기록을 DB에 추가하지 않는다.

단위 테스트는 진행 콜백을 켠 결과와 끈 결과가 동일하고, 최종 결과가 나오기 전에 작업 이벤트가 도착하는 것을 확인한다. 진행 메시지를 연출하기 위한 지연이나 추가 LLM 호출은 없다.
