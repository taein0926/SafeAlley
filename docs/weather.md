# 시간대별 날씨와 지도 테마

## 현재 연결 상태

**기상청 단기예보와 한국천문연구원 출몰시각 API만 사용한다.**
`KMA_SERVICE_KEY`, `KASI_SERVICE_KEY` 두 키가 필요하다. `safealley` Docker 프로젝트의 `weather`
배치가 시작 즉시 및 매시간 수집한다. 별도 테스트용 Docker 프로젝트를 실행할 필요가 없다.
실패하면 캐시를 보존하고 5분 후 재시도한다. 화면은 발표 후 6시간이 지난 예보를 숨긴다.
키가 없거나 공식 자료가 없으면 다른 업체의 데이터로 대체하지 않는다.
사용자 GPS, 계정별 위치, 검색한 출발지/목적지를 기상 API로 전송하지 않는다.
주안역 주변 고정 좌표 WGS84 `37.4649, 126.6804`에 해당하는 미추홀구
**고정 대표 격자 55,124** 예보와 인천 일출·일몰을 사용한다.
거리별 미세기후, 도로 침수·결빙, 시설 작동 상태를 보장하는 정보가 아니다.

## 기본 연결

```powershell
docker compose up -d --build
```

- backend가 migration `0014`까지 적용하고 정상 기동하면 같은 프로젝트의 날씨 배치가 시작한다.
- 기상청의 시간별 기온(°C), 풍속(m/s), 하늘 상태, 강수 형태·확률과
  한국천문연구원의 당일 일출·일몰을 받아 DB에 저장한다.
- `/api/weather`의 `forecast.provider=kma`, `forecast_status=available`,
  `solar.provider=kasi`, `theme_source=official_solar`, 당일 `solar_date`로 확인한다.
- 일출·일몰은 천문 계산값이며 현장 실측값이 아니다. 화면에는 기상청 출처 배지만 표시하고,
  한국천문연구원 일출·일몰은 테마 판정에 사용한다. 출처와 시각은 API 응답으로 확인한다.
- 외부 수집은 `data_pipeline/`에서만 수행하며 웹 요청은 DB 캐시만 읽는다.
  날씨 서비스는 공개 포트 없는 배치 실행기이며 API 서버가 아니다.
- 수집 주기는 `WEATHER_REFRESH_SECONDS=3600` (10분~6시간 범위), 실패 재시도는 5분.
  Docker Desktop에서는 **safealley 프로젝트 전체**를 시작하면 된다.

## 사용하는 공식 데이터

- [기상청 단기예보 조회서비스](https://www.data.go.kr/data/15084084/openapi.do):
  `getVilageFcst`, TMP(°C), WSD(m/s), SKY, PTY, POP.
  [기상청의 기능·변수 안내](https://apihub.kma.go.kr/apiList.do?seqApi=10), 4.3 단기예보조회 참고.
- [한국천문연구원 출몰시각 정보](https://www.data.go.kr/data/15012688/openapi.do):
  `getAreaRiseSetInfo`, `location=인천`, `locdate=YYYYMMDD`.
  일출·일몰은 기상청이 아닌 **한국천문연구원** 자료이며 API의 `solar.provider=kasi`로 구분한다.
- 기상청 API허브는 별도의 인증키 발급 경로다. 공공데이터포털 키와 호환되는 것으로
  간주하지 말 것. 현재 수집기는 공공데이터포털 `serviceKey` 방식이다.

## 활성화 (키는 채팅·Git에 올리지 말 것)

1. 위 두 공공데이터포털 서비스의 활용 승인을 각각 받는다.
2. 서버 비밀 환경변수에 `KMA_SERVICE_KEY`, `KASI_SERVICE_KEY`를 설정한다.
   `.env`를 이용할 경우 Git 제외 여부를 확인하고 권한을 제한한다.
   키를 `VITE_*`, 브라우저, URL 기록, 소스코드에 넣지 않는다.
3. `KMA_GRID_NX`, `KMA_GRID_NY`를 비워두면 주안역 고정 좌표를 기상청 공식
   [convertDfsGrid 변환식](https://www.weather.go.kr/w/resources/js/fn.js)으로 변환한 **55,124**를 사용한다.
   격자를 직접 설정할 때는 두 값 모두 입력하고 공식 지점 목록과 대조한다.
   `KASI_LOCATION`은 기본 `인천`. 다른 지역으로 변경할 때 화면의 지역 표시도 함께 검토한다.
4. backend 시작 시 migration `0014` 적용 확인 후 설정을 반영하고 필요 시 즉시 수집한다.

```powershell
docker compose up -d --build weather
docker compose --profile tools run --rm --build pipeline collect-weather
```

5. `/api/weather?departure_time=18:30`에서 `forecast_status=available`,
   `forecast.provider=kma`, 당일 `solar_date`를 확인한다.
   `solar.provider=kasi`, `theme_source=official_solar`이어야 한다.
6. `weather` 서비스가 매시간 실행한다. 서버 시작 직후 및 자정 이후에도 자동 갱신한다.
   반환 코드 1은 설정 누락 또는 한쪽 이상의 수집 실패. 기존 유효 캐시는 삭제하지 않는다.

## 동작과 한계

- 구조: 일회성 `data_pipeline` 수집 → DB 캐시 → FastAPI → Frontend.
  웹 요청이나 지도 이동마다 기상청을 호출하지 않는다.
- 기상청은 매일 02/05/08/11/14/17/20/23시 발표 중 15분 여유를 둔 최신 회차를 요청한다.
  호출 실패 시 다음 배치에서 재시도한다. 화면은 발표 후 6시간이 지난 예보를 숨긴다.
- 한 기관의 장애가 다른 기관의 정상 수집을 막지 않는다. 없는 자료는 생성하지 않는다.
- 오늘(한국시간)의 검색에 적용한 출발 시간이 18:30이면 18시 예보 값을 표시한다.
  해당 시간 자료가 없으면 다른 시간 예보로 대체하지 않는다. 날짜 선택은 아직 미지원.
- 일출 이상, 일몰 미만이면 낮. 자료가 없으면 기존 06–20시 기준을 임시 사용하며
  API의 `theme_source=fallback`으로 구분한다.
  과거 날짜의 일출·일몰을 오늘 것으로 쓰지 않는다.
- 출발 시간 입력 중에는 테마/예보를 바꾸지 않고, 직접 검색 제출 시 적용한다.
  AI 검색은 해석된 출발 시간, 시간이 없으면 검색 완료 시 현재 시간을 적용한다.
- 비·비/눈·소나기는 우산, 눈은 눈송이, 맑음은 해, 구름 많음·흐림은 구름으로 구분한다.
  강수 자료가 없으면 맑음으로 단정하지 않는다. 기온은 선택 시간의 예보 기온이며 일 최고기온이 아니다.
- 지도 테마와 경로 탐색/추천의 낮·밤 판정은 같은 당일 일출·일몰 자료를 사용한다.
  자료가 없거나 캐시를 읽지 못하면 06–20시를 낮으로 판정한다. 시간 미지정 요청은 한국 현재 시각을 사용한다.
- 낮에는 가로등을 안전도·A* 비용·추천 순위에서 제외한다. CCTV와 도움시설의 기존 비율을 재정규화한다
  (기본값 0.40:0.20 → 2/3:1/3). 밤에는 기존 저장된 종합 안전도와 야간 가중치를 유지한다.
  DB의 원본 점수와 재사용 그래프는 수정하지 않으며, 가로등 지도 표시 토글과 점수 반영 여부는 별개다.
- 테스트의 날씨·일출값은 합성 fixture이며 실제 기상청 관측값으로 노출하지 않는다.
  2026-09-23 로컬 두 키로 기상청 격자 55,124 예보와 한국천문연구원 인천 일출·일몰 실호출을 확인했다.
  키나 인증 포함 URL은 기록하지 않는다. 이미 적용된 DB migration `0013`·`0014` 이력은 보존한다.

## 화면 변경

- AI 검색을 첫 번째·기본 탭으로 표시.
- 날씨 창 좌상단에는 흰 글씨의 기상청 출처 배지를 표시하고 검색창은 날씨 창 아래에 배치.
- 시설 토글 하단에 접기 버튼을 연결하며 접으면 펼치기 버튼만 오른쪽 가장자리에 남김.
- 건물과 안전지원시설 정보창에서 출발·도착을 선택할 수 있으며 지도상의 좌표로 검색.
- 예상 도보 시간은 거리 ÷ 1.2m/s를 분 단위로 올림하며 신호 대기·개인 보행속도는 미반영.
- 추천 경로와 별도 최단/안전 경로를 함께 표시하고 선택한 경로만 파란색 사용.
  동일한 형상의 후보는 중복으로 그리지 않으며 겹치는 구간은 파란 선이 위에 놓인다.
- 서버가 평가한 조건을 `recommendation_factors`로 반환하여 추천 설명 위에 아이콘 표시.
  추천 보류 또는 지원되지 않는 조건은 추천 근거 아이콘으로 표시하지 않는다.
  회피 아이콘은 조건 반영 의미이며 계단·교차로의 실제 부재를 보장하지 않는다.
