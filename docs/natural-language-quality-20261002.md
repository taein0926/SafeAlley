# 자연어 경로 요청 해석 개선 (2026-10-02)

## 기준 환경

- 코드 기준: GitLab main `649887b`에서 만든 로컬 브랜치 `codex/intent-quality-20261002`
- 통합 실행: `safealley-colleague` Compose 프로젝트의 `3002` 화면, `8001` FastAPI, `safealley-colleague_postgis_data` 볼륨
- 이 DB는 담당자 전달 백업을 복원한 로컬 스냅샷이다. 담당자 컴퓨터의 DB와 실시간 동기화되지는 않는다.
- 별도 `3001/8000` 로컬 앱은 혼동 방지를 위해 중지했고, 그 DB 볼륨은 삭제하지 않았다.

## 발견한 문제와 수정 원리

Qwen3:4b가 자연어를 먼저 Structured Output으로 해석하는 구조는 유지했다. 모델, Tool Router, 장소 Resolver, 경로 알고리즘은 교체하지 않았다. 수정 범위는 FastAPI 백엔드의 출력 검산이다.

1. **정정한 출발 시각이 거절됨.** “오전 8시가 아니라 오전 9시 15분”에서 모델이 09:15를 출력해도 기존 검증은 첫 시각 08:00과 비교해 응답을 거절했다. 이제 시각 표현의 역할을 출발·도착·미지정으로 구분하고, 명확한 정정이 있을 때 확정된 출발 시각을 검증한다.
2. **도착 예정 시각을 출발 시각으로 오해할 수 있음.** “오후 2시에 도착”만 말한 경우 `departure_time`은 비워 둔다. 도착 시각과 출발 시각이 함께 있으면 출발 시각만 사용한다. 여러 시각의 관계가 모호하면 코드가 임의로 시간을 덮어쓰지 않는다.
3. **도착 기한만으로 최단거리 선호가 추가됨.** “오후 2시까지 도착”은 `distance_m/minimize` 요청과 다르다. 도착 기한이 있고 명시적인 짧은 길 요청이 없을 때만 모델이 추가한 거리 선호를 제거한다. “짧은 길로”가 함께 있으면 유지한다.

새 프롬프트 문구를 시험했을 때 기존 두 문장의 조건 추출이 흔들려 프롬프트 수정은 되돌렸다. 특정 문장마다 예외를 더하는 대신 역할 구분과 명시적 조건 검산을 적용했다.

## 새 질문 분리 평가와 후속 개선 (2026-10-02)

기존 195문장은 이미 개발 중 보았으므로 실제 새 질문 정확도로 해석할 수 없다.
이를 확인하기 위해 기존 문장과 중복되지 않는 한국어 질문 60개를 별도로 작성했다.
유형은 중립·허용, 비교, 정정, 시간 역할, 복합조건, 장소 누락, 미지원 조건이다.
각 질문에 출발지·도착지·출발 시각·선호조건의 기대값을 먼저 기록했다.
30개는 오류 진단용, 다른 30개는 코드 고정 뒤 첫 실행용으로 분리했다.

이 60개는 Codex가 작성하고 자체 확인한 임시 라벨이다. 팀원/사용자가
직접 작성하고 독립적으로 정답을 승인한 사람 검수 평가셋은 아직 아니다.
첫 실행용 30개도 프로그램에 처음 넣었다는 뜻이지, 실제 사용자 분포를
대표하는 무작위 표본이라는 뜻이 아니다.

진단용 30개 첫 실행은 23/30이었다. 유형별로 정정 1/5, 비교 5/5,
중립 4/5, 시각 4/5, 복합조건 4/5, 장소 누락 2/2, 미지원 3/3이었다.
주요 실패는 정정 전 조건이 남거나 새 조건이 빠지는 일, 도착 기한을
출발 시각으로 읽는 일, 평탄함을 지원 지표가 아닌 별도 factor로 내는 일이었다.

다음 순서로 수정하고 같은 질문을 재실행했다.

1. FastAPI 검산에서 시각 뒤에 장소명이 끼어 있어도 도착 역할을 인식하도록
   했다. 도착 기한만으로 출발 시각이나 최단거리 요청을 만들지 않는다.
2. Qwen이 평탄함을 flatness라고 출력할 때 지원 지표인
   max_slope_percent/minimize로 정규화했다. 기존 평지 재시도 보호는 유지했다.
3. 프롬프트에 정정 지시 한 줄을 시험했지만 정정 실패가 개선되지 않아
   되돌렸다. 최종 버전은 Qwen3:4b와 기존 프롬프트를 유지한다.
4. 명시적인 아니, 정정할게, 다시 말하면 뒤의 최종 조건을
   FastAPI의 Python 코드에서 재확인했다. 취소된 조건만 제거하고,
   뒤에 명시한 조건만 반영한다. 계단은 빼고는 계단 회피이고,
   CCTV는 빼고는 CCTV 선호 취소라는 차이도 구분한다.

최종 검증은 기존 회귀 195/195, 진단용 30/30, 백엔드 단위 테스트
234개 통과였다. 여기까지는 이미 본 질문의 회귀 검증이다.
코드 고정 뒤 처음 실행한 예약 30개는 27/30이었다. 실패는
계단은 몇 개 있어도 괜찮아를 계단 최소화로 읽은 1건,
생각이 바뀌었어 뒤의 계단 취소를 반영하지 못해 출력 오류가 난 1건,
정확히는 건널목이 적으면 돼를 완전 회피로 읽은 1건이다.
요청하지 않은 조건 1건, 필요한 조건 누락 1건, 조건 방향 오류 1건
(출력 오류 1건과 겹침)이었다. 예약셋은 이 결과를 본 순간 더 이상
미공개가 아니므로 이번에는 그 세 문장에 맞춰 코드를 추가 변경하지 않았다.

평가 대상은 자연어 구조화 단계다. 지도상 실제 보행 가능 여부나
장소 Resolver의 좌표 정확도, 경로 추천 안전성은 별도의 검증이 필요하다.
다음 독립 평가는 담당자가 새로 작성한 문장과 사람이 확인한 정답으로
진행해야 한다. 이 시점까지 Qwen 모델은 교체하지 않았고 GitLab에
푸시하지 않았다. 이후 MR 준비는 아래에 별도로 기록한다.

재현:

```powershell
docker compose -p safealley-colleague exec -T backend python -m pytest -q tests/unit
docker compose -p safealley-colleague exec -T backend python -m evals.evaluate_intent --set time_role_probe --quiet
docker compose -p safealley-colleague exec -T backend python -m evals.evaluate_intent --set all --quiet
```

## 새 문장 보정과 MR 검증 (2026-10-02)

기존 예약 30개의 첫 점수 27/30에서 실패한 세 가지를 고쳤다. 모델이
계단 허용 문장을 계단 최소화로 내거나, 나중에 취소한 계단 회피를
유지하거나, 건널목을 "적게" 건너라는 정정을 완전 회피로 해석했다.
FastAPI 백엔드는 Qwen 출력을 받은 뒤 마지막 조건 언급과 명시적인
허용·정정 표현을 확인한다. `stairs_count` 같은 모델 표기는
Tool Router가 쓰는 `stairs_distance_m`으로 정규화한다.
Qwen3:4b 모델과 프롬프트, 경로 탐색 코드는 바꾸지 않았다.

별도 추가 문장 20개의 첫 점수는 17/20이었다. 처음에는
"계단 한두 군데는 지나가도 괜찮아", "조명은 따지지 않을게"를
요청 조건으로 잘못 남기고, "정확히는 조금 적게 건너면 돼"를
완전 회피로 남겼다. 일반적인 허용·무관·정정 표현을 보강한 뒤
회귀 점수는 20/20이었다.

또 다른 20개는 이 보정 전에 기대값을 적어 두고 처음 실행했다.
첫 점수는 17/20이었다. 실패는 "건널목은 거쳐도 돼"와
"CCTV는 많든 적든 괜찮아"를 조건으로 추가한 2건,
"다시 생각해보니 적게"를 완전 회피로 유지한 1건이었다.
경사가 완만해야 한다는 방향을 반대로 낸 것도 겹쳤다.
이 표현군을 공통 규칙으로 보정한 뒤 회귀 점수는 20/20이었다.

따라서 20/20은 처음 보는 문장에 대한 성능 수치가 아니다.
코드 변경 전 첫 실행 점수 17/20을 별도로 보존한다. 모두 Codex가
작성·자체 검토한 질문이며, 사람 검수나 실제 사용자 문장 평가가
끝났다는 뜻도 아니다. 이 단계에서 단위 테스트 243개가 통과했고,
장소 좌표, 실제 경로 안전성과 보행 가능 여부는 이 자연어 구조화
평가의 대상이 아니다. 담당자 DB 스냅샷에 연결된 FastAPI 8001 API에서
Qwen3:4b가 계단 허용을 조건에서 빼고 CCTV 우선을 전달했으며 경로
후보 2개가 생성됐다. "횡단보도 적게"도 완전 회피가 아닌 최소화로
전달됐다. 이 두 번째 질의의 추천 상태는
`no_supported_preferences`였으므로, 문장 해석 성공과
해당 후보의 추천 지표 지원 여부는 구분해야 한다.

## 최종 수용 평가와 검증 완료

이미 보정에 사용한 문장과 중복되지 않는 질문 20개를 추가로 작성하고,
기대하는 출발지·도착지·시각·조건을 먼저 고정했다. 실제 Qwen의 첫
실행 점수는 18/20이었다. "계단은 있어도 무방해"에서 계단 회피를
추가한 오류와, "생각이 바뀌었어. 몇 번은 건너도 돼" 뒤에도 건널목
최소화를 유지한 오류였다. 두 문장만 예외 처리하지 않고 허용 표현과
생략된 대상에 대한 정정 처리 범위를 넓혔다. 보정 후 이 20문장의
회귀 점수는 20/20이다. 18/20 첫 점수는 그대로 보존한다.

최종 코드에서는 단위 테스트 245개, 기존 195문장 195/195,
추가 질문 다섯 세트 120/120을 실제 Qwen3:4b로 다시 실행해
통과했다. 합계 315문장의 완료된 회귀 평가에서 조건 누락,
요청하지 않은 조건 추가, 조건 방향 오류는 0건이었다.
하지만 120문장 모두 자체 작성·자체 검토했으며 여러 세트는
실패를 보고 수정한 뒤의 회귀 평가다. 따라서 315/315를 실제 사용자
문장의 일반화 정확도로 해석해서는 안 된다.

담당자 DB 스냅샷을 연결한 최종 FastAPI 8001 환경에서도 두 실패
문장을 다시 요청했다. "계단은 있어도 무방해"는 계단 조건 없이
CCTV 우선만 전달했고, "생각이 바뀌었어. 몇 번은 건너도 돼"는
건널목 조건 없이 가로등 우선만 전달했다. 각각 경로 후보 2개와
추천 상태 `ready`를 반환했다. 실행 중인 백엔드 이미지의
단위 테스트도 245개가 통과했다.
