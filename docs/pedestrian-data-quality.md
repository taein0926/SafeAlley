# 보행·시설 데이터 품질

## 현재 원칙

OSM 보행 도로/계단/건널목 태그와 실제 연결 정보를 사용합니다.
공식 횡단보도 POI의 근접만으로 새로운 횡단 가능 edge를 만들지 않습니다.
허용된 일반 도로 연결은 남기고 우선 보행망 바깥 거리를 먼저 최소화합니다.
현장 검증 없는 지도 태그를 안전 인증으로 취급하지 않습니다.

가로등/CCTV/안전시설은 등록 위치의 거리·밀도·공백 proxy입니다.
실제 조도/점등·운영 상태·범죄 확률을 뜻하지 않습니다.
현재 CCTV는 정밀 GeoJSON 좌표 품질을 사용하며 과거 저정밀 셀 집계 수치를
현재 서비스 현황으로 설명하지 않습니다.

## 원천과 분석

- 건물: MOLIT GIS SHP. [필드/좌표/원천](building-data.md).
- 가로등: 제공된 공식 CSV/도로시설 POI, 실제 DB source를 구분합니다.
- CCTV: cctv_michuhol_ai_ready.geojson; 정밀 좌표 및 품질 metadata 보존.
- 안전시설: 경찰/119/병원 category와 출처를 보존합니다.
- 계단: highway=steps와 is_steps, 원본에 있는 incline/step_count 등만 사용합니다.
- 건널목: OSM 횡단 그룹/노드; 자료가 불완전하면 전체 횟수 비교는 보류합니다.
- 육교: 실제 OSM bridge/layer topology와 참조 매칭만 연결하며 임의 통행선을 만들지 않습니다.
- 경사도: 알려진 incline/검증된 DEM만 지표로 사용하고 미측정을 0으로 대체하지 않습니다.
- 유동인구: 실제 연동되지 않았으며 추천 지원 지표로 만들지 않습니다.

## 검증과 갱신

원본 좌표계·도형 유효성·출처 식별자·통행 방향·연결 node를 확인합니다.
데이터 갱신 후 도로/계단 건수·geometry·시설 좌표 품질·분석 coverage를 이전 백업과 대조합니다.
41 Way/77 segment 같은 이전 수치는 해당 snapshot 기준이며 새 데이터의 고정 상수가 아닙니다.
분석용 도로 분할은 원본 graph topology를 바꾸지 않습니다.

모든 후보에 미검증 대로가 있다는 이유만으로 추천을 무조건 막는 옛 정책은 현재와 다릅니다.
내부 비교에서 metadata를 활용하되 폐기한 대로 경고는 결과에 추가하지 않습니다.
강한 avoid/지원 지표/자료 부족 처리는 [라우팅](routing.md) 정본을 따릅니다.

현재 서비스에서 제거된 전체 도로 검사 오버레이와 저정밀 CCTV·옛 DB snapshot의
경로 성능/안전 검증 기록은 이 문서에서 제거했습니다.
공식 원천/라이선스는 [NOTICE.md](../NOTICE.md), 적재는 [data-pipeline.md](data-pipeline.md),
회귀 검증은 [testing.md](testing.md)를 따릅니다.
