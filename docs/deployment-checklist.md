# SafeAlley 사내 서버 배포 준비 체크리스트

갱신일: 2026-09-23. 소규모 사내 시범 운영, 승인된 외부 접속 허용을 전제로 한다.
아래 미완료 항목은 서버에서 별도로 준비/검증해야 한다. GitLab push만으로 배포되지는 않는다.
배포할 `main`의 정확한 commit hash, 이미지 식별자, DB 백업 시점을 배포 기록에 남긴다.

## 1. 서버·접근 제어

- [ ] 서버 OS, CPU/RAM, GPU/VRAM, 디스크와 예상 동시 사용자 수를 확인한다.
- [ ] Docker Engine/Compose 사용 승인, 운영 담당자와 저장소 경로를 확정한다.
- [ ] 사내 DNS·HTTPS 인증서·방화벽·인증 게이트웨이를 준비한다.
  현재 `user_id`는 브라우저 가명 식별자이며 로그인/접근 제어가 아니다.
- [ ] 단일 서버 Compose를 기준으로 배포용 설정을 준비한다. 현재 localhost 포트 바인딩은
  다른 PC에서 직접 접근할 수 없으므로 승인된 HTTPS reverse proxy를 통해 frontend와 `/api`를 제공한다.
  DB·backend·Ollama 포트는 직원 PC나 외부 인터넷에 직접 노출하지 않는다.
- [ ] 서버 전용 환경변수와 강한 DB 비밀번호를 관리한다. 실제 비밀정보를 Git, 이미지,
  로그에 넣지 않는다. `VITE_*`는 빌드 시 공개 코드에 포함되므로 비밀값을 넣지 않는다.

## 2. DB·공간 데이터 이관

- [ ] 현재 검증된 PostgreSQL/PostGIS DB를 일관된 백업으로 이관하고 별도 환경에서 복원한다.
  Git clone만으로 건물·CCTV·도로·가로등·장소 데이터가 생기지는 않는다.
- [ ] 원본/가공 파일은 승인된 별도 저장소에 이관하고 출처·수집일·체크섬을 기록한다.
  `data_pipeline/raw/`, `processed/`, `.env`는 Git에서 제외된다.
- [ ] 개발용 사용자 추천·선택 기록은 이관본에서 제외/정리한다. 현재 개발 DB 원본을 임의 삭제하지 않는다.
- [ ] 정밀 CCTV 좌표와 safety_score, 건물, 가로등, 안전시설, 장소, OSM 보행망이 보존됐는지 확인한다.
- [ ] 계단 41 Way / 77 segment, 교차로 참조 341건, 육교 참조 9건을 확인한다.
  현재 육교 경로망 연결은 3건이며 나머지 6건을 실제 연결 경로로 취급하지 않는다.
- [ ] OSM 재적재 시 계단 속성과 교차로/육교 연결 정보를 다시 적용한다.
  legacy `OSM_SAFETY_SCORE_MODE=demo`로 검증된 안전도를 덮어쓰지 않는다.
- [ ] Alembic `current`, `heads`, `history`를 확인한다. 현재 정본 head는 **0012 단일 head**이며,
  이번 AI 성능·지도 UI 변경에는 새 migration이 없다.
- [ ] 배포 절차는 DB 백업 → migration → 앱 시작 → 검증으로 정한다.
  현재 backend 시작 명령에 `alembic upgrade head`가 포함되어 있음을 운영 절차에 반영한다.

## 3. Ollama·AI 검색 — 이번 변경 반영

현재 설정 기본값은 다음과 같다. 실제 `.env`에 새 항목이 없어도 Compose 기본값이 적용된다.

| 설정 | 기본값 | 확인 사항 |
|---|---|---|
| `OLLAMA_BASE_URL` | `http://host.docker.internal:11434` | 서버 OS/배치 방식에 맞춰 컨테이너에서 접근 가능한 주소 설정 |
| `OLLAMA_MODEL` | `gemma4:26b` | 서버에서 동일 모델 준비, GPU 인식과 메모리 확인 |
| `OLLAMA_TIMEOUT_SECONDS` | `300` | 모델 초기 로딩과 오류 처리 시간 검증 |
| `OLLAMA_KEEP_ALIVE` | `10m` | 요청 후 모델 유지 시간, 다른 GPU 작업과 메모리 경합 확인 |
| `OLLAMA_INTENT_CACHE_SECONDS` | `300` | 검증된 동일 문장의 분석만 메모리 캐시, `0`이면 비활성화 |

- [ ] Ollama 설치·모델 다운로드와 재부팅 후 자동 실행을 준비한다. Compose에는 Ollama 서비스가 없다.
- [ ] 모델 미로딩, 로딩 완료 후 새 문장, 동일 문장 재검색을 분리해 응답 시간을 측정한다.
  로컬 표본은 웹 검색 34.28초/재검색 3.49초였으나 서버 성능 보장이 아니다.
- [ ] 분석 캐시는 프로세스별 최대 128개이며 재시작 시 초기화된다.
  사용자 데이터 취급 정책에 맞춰 TTL을 정한다. 경로·장소·개인화 결과는 캐시하지 않는다.
- [ ] 요청 내 후보 3개는 도로 그래프를 공유하지만 다음 요청은 DB를 다시 읽는다.
  예상 동시 사용자 수로 DB 부하와 응답 시간을 검증한다.
- [ ] 같은 문장의 동시 첫 요청은 각각 LLM을 호출할 수 있으므로 동시 요청과 대기열을 확인한다.
- [ ] 사내 proxy의 `/api/agent/query` timeout을 검토한다. 현재 앱 nginx는 660초,
  LLM은 의미 검증 실패 시 최대 1회 재요청한다. 캐시가 있다고 무조건 timeout을 줄이지 않는다.
- [ ] 실제 자연어 출발지/목적지, 시간 미지정, 야간 시간, 계단 회피, 복합 선호조건을 검증한다.
- [ ] 추천 후 선택 저장 API가 200을 반환하고 `intersection_distance_m` 학습에 오류가 없는지 확인한다.
  기존 사용자 기록은 유지하며 배포 테스트용 사용자를 분리한다.

구현 및 상세 측정: [AI 검색 처리와 캐시](ai-search-performance.md).
모델 유지 설정 근거: [Ollama Chat API](https://docs.ollama.com/api/chat).

## 4. 외부 접속·클라이언트 지도

- [ ] 직원 PC에서 OSM 타일 접속, 서버에서 Nominatim 접속을 각각 승인/검증한다.
  이미지·패키지·모델 다운로드에 필요한 구축 시 외부 접속은 실행 중 접속과 별도로 관리한다.
- [ ] OSM 출처 표시와 캐시 정책을 유지한다. 공개 타일 대량 선취/오프라인 수집은 하지 않는다.
  [OSM 타일 정책](https://operations.osmfoundation.org/policies/tiles/)을 확인한다.
- [ ] Nominatim 식별 User-Agent, 장소 캐시와 앱 전체 초당 1회 제한을 지킨다.
  현재 요청 간격 제한은 프로세스 내부이므로 다중 worker/인스턴스로 늘릴 때 별도 검토한다.
  기밀 장소명을 외부 검색에 보내지 않도록 안내한다.
  [Nominatim 정책](https://operations.osmfoundation.org/policies/nominatim/)을 확인한다.
- [ ] 사내 브라우저의 WebGL/하드웨어 가속 및 지도 조작 성능을 확인한다.
- [ ] 가로등의 밝은 중심점/빛 번짐, 표시 토글과 객체 정보 클릭을 확인한다.
  빛 번짐은 위치 강조용이지 실제 조도·점등 상태·안전 보증이 아니다.
- [ ] 기본 배경 밝기 0.68, 야간 0.26에서 지도 글자·건물·파란 경로선이 구분되는지 확인한다.
  기존처럼 출발 시간 편집만으로는 테마가 변하지 않고 경로 검색 실행 후 적용되는지 확인한다.
- [ ] 안전도·계단 회피·교차로 회피가 `낮음 / 중간 / 높음` 세 단계로만 선택되는지 확인한다.
  내부 가중치는 기존 0/50/100(계단·교차로 API는 0/0.5/1)이고 기본값은 낮음이다.
  `높음`도 무계단 경로나 육교 사용을 보장하지 않는다.
- [ ] 낮에는 가로등을 안전도·경로 탐색 비용·추천 순위에서 제외하고, 밤에는 기존 종합 점수를 사용하는지 확인한다.
  당일 일출·일몰(미연결 시 06–20시) 판정과 지도 테마가 일치해야 한다.
  backend의 `SAFETY_CCTV_WEIGHT`/`SAFETY_HELP_POINT_WEIGHT`는 pipeline과 같은 값으로 설정한다.
- [ ] 지도에서 파란/회색 경로 클릭 시 선택·색상·결과 카드가 함께 바뀌고, 닫은 결과창이 다시 열리는지 확인한다.
- [ ] 주안역 초기 화면, 건물 구역 캐시, 시설 토글, 계단/육교 아이콘, 지도 건물 선택,
  직접/AI 검색, 도보 1.2m/s(72m/분) 기준 예상 소요 시간(분 단위 올림)과 교차로 우회 상한을 확인한다.

## 5. 검증·배포·운영

- [ ] commit으로 고정한 backend/frontend 이미지와 이전 이미지·설정을 보관한다.
  새 `main`을 자동 추적해 검증 없이 배포하지 않는다.
- [ ] 별도 검증 DB에서 backend 전체 테스트, data pipeline 테스트, frontend 테스트와
  production build를 실행한다. 개발 데이터용 테스트를 운영 DB에 바로 실행하지 않는다.
- [ ] 로컬 확인 기준: backend **96 passed**, frontend **37 passed**, production build 성공,
  실제 LLM **4문장 통과**. Pipeline의 이전 검증은 **39 passed, 2 skipped**이며 이번 변경에는
  pipeline 코드 변경이 없다. 서버에서는 skip 원인을 포함해 다시 검증한다.
- [ ] 사내 PC에서 최단/안전 경로, 계단 가중치, 교차로 우회, AI 검색, 선택 저장을 최종 점검한다.
- [ ] backend/DB/지도 상태, LLM 실패율·지연, 로그 회전·디스크 사용량을 점검한다.
  캐시 로그는 문장이 아닌 적중 여부/소요 시간만 사용한다. 로그 수집 수준도 확인한다.
- [ ] 일일·배포 전 DB 백업, 보존기간/접근권한과 실제 복원 연습을 준비한다.
- [ ] 서버 재부팅 후 앱·DB·Ollama 자동 복구와 healthcheck를 확인한다.
- [ ] 이전 이미지 복귀와 DB 복원 절차를 문서화한다. 앱 롤백이 DB 롤백을 자동으로 수행하지는 않는다.
- [ ] 운영 담당자 승인 후 시범 운영을 시작한다. 배포 commit, 검증 결과, 잔여 제약을 기록한다.

권장 순서: 서버/정책 확정 → DB·원본 백업 → 배포 설정/인증/Ollama 준비 →
검증 환경 복원·테스트 → 사내 PC 인수 확인 → 시범 운영.
