# 문장 해석과 요구사항 미리보기

## 최종 검색

POST /api/agent/query/stream → Ollama structured output → Pydantic·의미 검증 →
공통 장소 resolver → 허용된 rank_routes → 실제 진행·최종 후보.
SQL·좌표를 모델이 임의 생성하도록 하지 않습니다.

출발/도착 역할·출발 시각·선호 방향을 확인하며 요청하지 않은 장소/시각/조건을 만들지 않습니다.
부정·허용·철회·뒤의 수정, 비교에서 제외한 조건, 한글 시각, 강한 avoid와 부드러운 minimize를
구분합니다. 제한된 원문 검산은 모델의 모든 새 표현을 이해하는 보장이 아닙니다.
형식·의미 실패는 최대 1회 보정 요청하며 연결 실패는 오류로 반환합니다.
다른 모델이나 임시 해석으로 조용히 성공 처리하지 않습니다.

자연어 검색은 explicit_only로 명시 요청 조건을 보존하고 과거 선택 선호를 몰래 섞지 않습니다.
계산 기본값과 화면에 사용자가 요청했다고 표시하는 조건은 구분합니다.
시각 미지정 시 계산의 현재 시간 정책이 사용돼도 특정 시각을 요청했다고 만들지 않습니다.
장소 문자열은 places → 지역 제한 GIS building → Nominatim의 공통 resolver를 사용합니다.
이름과 주소가 같은 비주거 시설의 여러 건물은 하나의 시설로 해석합니다. 같은 주소의 공동주택에 여러 동이 있으면 임의의 동을 고르지 않고 단지로 지도를 이동해 출발/도착 건물을 직접 선택하게 합니다. 여러 주소에 해당하면 전체 주소 입력을 요청합니다.

## 입력 중 미리보기(Jev)

입력 중 전체 문장은 별도 TypeSafe API로 전달될 수 있으므로 민감한 주소/개인정보 입력을 주의합니다.
JEV_PREVIEW_ENABLED=true와 서버 TYPESAFE_API_KEY가 모두 필요하며 기본은 비활성화입니다.
상태 API는 enabled/configured/available만 반환하고 키를 노출하지 않습니다.
이는 유료 외부 서비스이고 Ollama 문장 검색과는 별개입니다.

카드는 distance/streetlight/cctv/safety / stairs/crossing/bridge/time 순서입니다.
analyzing/applied/not_applied, direction/confidence/period/judgment를 보존합니다.
Jev 응답 뒤에는 8개 고정 카드 공통 원문 검증을 수행합니다. 원문에 없는 항목은 Jev가
연관 항목으로 추론해도 not_applied이고, 명시된 조건의 방향이 완성됐으면 Jev의 긍정 판단을
신뢰도 숫자만으로 버리지 않습니다. 명사·시간대만 입력한 미완성 표현은 analyzing,
철회·허용은 not_applied, 명확한 원문과 Jev가 충돌하면 analyzing입니다. 따라서 육교 요청이
계단·건널목 카드를 켜거나 건널목 요청이 계단 카드로 확대되지 않습니다.
도움시설을 적게, 계단·건널목을 많게처럼 서비스가 지원하는 안전 방향과 반대인 요청은
Jev가 긍정으로 추론해도 applied로 표시하지 않습니다.
도움시설은 일반 명칭뿐 아니라 경찰서·지구대·파출소·소방서·119안전센터·응급실·
응급의료기관과 인접한 접근성 표현을 인식합니다. 이때 `경찰서가 가까운 길`의 `가까운`을
출발지-목적지 최단거리로 해석하지 않습니다. 경찰 접근성은 최종 검색에서 기존
`police_accessibility` 전용 지표를 유지하고 종합 `safety_score`를 중복 추가하지 않습니다.
`계단 말고 평지`처럼 장애물 뒤의 `말고`는 회피 요청이고, `최단거리 말고 안전한 길`처럼
선호 지표 뒤의 `말고`는 해당 선호 철회입니다. `피하고 싶지 않아`, `피할 생각은 없어`,
`아니어도 돼`, `많은 길은 싫어` 같은 부정·허용도 not_applied로 검증합니다.
`육교 싫어`는 육교 회피로 적용하지만 `육교 없는 길은 싫어`는 회피 요청의 철회로 구분합니다.
`안 할래`, `하지 않을게`, `신경 쓰지 마`, `줄일 생각 없어`, `싫지 않아`, `없어도 돼`도
철회·허용으로 처리합니다. `오후에`, `밤에`, `새벽에`, `아침에`처럼 조사가 붙은 완성 시간대는
주간·야간으로 적용하지만 단독 `오후`, `밤`은 입력 중인 표현으로 유지합니다. `밤이 아니야`는
시간 요청 철회입니다. 씨씨티비·감시카메라와 고가보도·보행육교 동의어도 포함합니다.
환한 길·조명이 잘 된 길·층계·지름길과 한글 시각(`오후 두 시`, `밤 열 시`),
저녁·야간 표현을 포함합니다.
띄어쓰기 경계와 마지막 단어 idle 처리·요청 묶기·캐시·늦은 응답 무시를 사용합니다.
브라우저는 탭마다 임의 미리보기 세션 ID를 헤더로 보내며, FastAPI의 0.75초 호출 간격은
전체 사용자 공통이 아니라 해당 세션 안에서만 적용합니다. 한 사용자의 입력이 다른 사용자의
실시간 분석을 429로 차단하지 않습니다. 세션 ID는 인증 정보나 사용자 신원이 아닙니다.
예시를 선택하면 문장 전체를 입력란에 한 번에 넣고 같은 미리보기 흐름으로 분석합니다.
예시 선택 자체는 길찾기를 실행하지 않습니다. 입력란은 바로 수정할 수 있으며,
Enter 또는 길찾기 버튼으로 검색하고 Shift+Enter로 줄바꿈합니다. 한글 조합을 확정하는
Enter와 키를 길게 눌러 발생한 반복 입력은 검색하지 않습니다.
문장 입력 모드의 조건 카드는 빈 입력·검색 중·성공/실패 후에도 검색창에 유지하고 직접 설정에서는 숨깁니다. 빈 입력은 미선택 상태이며
분석 호출/로딩 표시가 없습니다. 검색을 시작하면 미리보기 요청을 멈추고 마지막 판단을 보존합니다.
검색 중/검색 완료 결과를 입력 미리보기로 덮어쓰지 않습니다.
검색 완료 카드의 기준은 Jev가 아니라 Gemma 구조화 결과와 FastAPI가 실제 실행한
rank_routes의 recommendation_conditions입니다.
육교 독립 라우팅 가중치는 아직 없으므로 인식과 경로 적용을 구분합니다.

## 평가

단위/계약/UI mock은 실제 모델 정확도 평가가 아닙니다.
backend/evals에는 문장·역할·시간·조건 방향·회피·추가/누락을 비교하는 평가 도구와
회귀 문장이 남아 있습니다. 테스트에 사용된 문장을 새 독립 성능으로 부르지 않습니다.
실시간 카드의 표현 회귀 자료는
`backend/evals/live_intent_preview_regression_20261014.json`에 별도로 관리합니다. 이 파일은
도움시설 문맥, 부정·철회, 동의어, 한글 시각을 포함하는 개발 회귀셋이며 blind 정확도 자료가 아닙니다.
오래된 모델/DB/저정밀 CCTV 기반 경로 결과를 최신 정확도·안전 보장으로 사용하지 않습니다.

실제 모델 live 평가는 운영자의 외부 호출·부하 허용 범위에서 별도로 수행합니다.

아래는 소스가 있는 로컬 평가 환경 예시다. 현재 VM은 고정 runtime 설정을 사용하며,
운영 GPU live 평가는 승인 후 [평가 안내](../backend/evals/README.md)의 서버 명령으로 실행한다.

```powershell
# 실행 모델/설정과 공간 DB를 먼저 확인합니다.
docker compose run --rm --no-deps backend python -m evals.evaluate_intent --set dev --quiet
docker compose run --rm --no-deps backend python -m evals.route_progress_smoke
```

코드 변경 후에는 backend 이미지를 갱신하거나 현재 소스를 연결해야 합니다.
평가 상세 옵션은 backend/evals/README.md와 각 --help를 따릅니다.

[전체 회귀 검증](testing.md), [AI 연결](ai-setup.md).
