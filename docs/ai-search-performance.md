# AI 검색 처리와 캐시

## 경로 계산

`generate_route_candidates()`는 검색마다 `prepare_route()`를 한 번 호출한다.
출발/도착 노드 조회, 도로 데이터 조회, 그래프 구성을 공유하고 최단·안전·균형
경로의 탐색 비용과 균형 경로의 다양성 penalty만 각각 적용한다.

- 그래프는 검색 요청 안에서만 재사용한다. 전역 TTL 그래프 캐시는 사용하지 않는다.
- 다음 검색은 DB를 다시 조회하므로 CCTV/safety/계단/교차로 데이터 갱신을 반영한다.
- 단일 경로 API도 기존 동작을 유지한다.
- 계단 가중치와 교차로 우회 상한, 미검증 구간 처리 정책은 변경하지 않는다.

## 자연어 분석

Ollama의 모델과 JSON schema/의미 검증, 최대 1회 보정 재요청은 유지한다.
중복된 예시를 줄이고, 서버에서 보충 가능한 `profile=pedestrian`과 `weight=1`은
출력에서 생략하도록 지시한다. 사용자에게 반환하는 API schema는 바뀌지 않는다.
장소/시각/미지원 선호조건을 임의로 만들어서 지연을 숨기는 fallback은 없다.

- `OLLAMA_KEEP_ALIVE=10m`: 요청 후 모델을 메모리에 유지할 시간.
- `OLLAMA_INTENT_CACHE_SECONDS=300`: 검증 성공한 자연어 분석 결과의 유효 기간.
  `0`이면 캐시하지 않는다.
- 최대 128개를 프로세스 메모리에만 저장하며 재시작 시 사라진다.
- 앞뒤 공백 외에 문장을 변형하지 않는다. 문장, 모델, 접속 주소, 지시문이 다르면
  재분석한다. 실패 결과는 저장하지 않는다.
- 반환할 때 복사하므로 사용자 간 객체 변경이 전파되지 않는다. 캐시 접근은 잠금으로 보호한다.
- 장소 해석, 도로/경로, 추천 결과, 사용자 선호도는 이 캐시에 포함하지 않는다.
- 같은 문장의 동시 첫 요청은 각각 모델을 호출할 수 있다.
- 캐시 적중 여부와 처리 시간만 로그에 기록하며 문장/장소/사용자 ID는 기록하지 않는다.

모델이 내려간 뒤의 첫 요청과 처음 보는 문장은 여전히 LLM 연산 시간이 필요하다.
반복 검색의 개선치를 첫 검색의 보장 응답 시간으로 해석하지 않는다.
모델 옵션은 [Ollama Chat API](https://docs.ollama.com/api/chat)를 따른다.

## 선택 저장

`intersection_distance_m`는 작은 값이 좋은 학습 지표로 등록한다.
새 표시 지표가 추가되더라도 학습 방향이 명시된 지표만 학습하므로
미등록 방향 접근으로 `KeyError`가 발생하지 않는다.

## 검증

```sh
docker compose build backend
docker compose run --rm --no-deps backend pytest -q
```

회귀 테스트는 교차로 선호 저장 API, 미등록 지표 방어, 캐시 만료/상한/모델 구분/
실패 비저장/반환값 격리, 그래프 조회 1회 및 기존 경로와의 완전 일치를 확인한다.
통합 테스트는 전용 fixture 데이터와 테스트 사용자만 사용한다.
LLM 단위 테스트는 mock이므로 실제 모델 검증과 구분한다.
