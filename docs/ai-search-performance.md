# 검색 처리와 캐시

## 도로 그래프

generate_route_candidates는 검색마다 prepare_route를 한 번 실행합니다.
출발/도착 snap과 PostGIS 조회·그래프 구성을 최단·맞춤 후보가 공유합니다.
숨겨진 균형 후보나 다양성 penalty를 추가하지 않습니다.
그래프는 요청 내에서만 재사용하며 다음 검색은 DB를 다시 읽습니다.

현재 보행 우선/시설·계단·건널목 비용은 [routing.md](routing.md)를 따릅니다.

## 문장 해석 캐시

- OLLAMA_KEEP_ALIVE=10m: 검색 사이 모델 유지 시간.
- OLLAMA_INTENT_CACHE_SECONDS=300: 검증된 해석만 프로세스 메모리에 저장, 0이면 비활성화.
- 최대 128개, 재시작 시 초기화. 장소/도로/추천/사용자 선호 결과는 이 캐시에 포함하지 않습니다.
- 문장·모델·주소·지시문을 구분하고 실패는 저장하지 않습니다.
- 반환 객체를 복사하고 캐시 접근은 잠금으로 보호합니다.
- 같은 문장의 동시 첫 요청은 각각 모델 호출을 할 수 있습니다.
- 로그에는 적중/처리시간만 남기며 문장·장소·user_id를 기록하지 않습니다.

새 문장/모델 초기 로딩은 별도 시간이 필요합니다. 예전 PC/모델의 초 단위 수치를
현재 서버 성능 보장으로 사용하지 않습니다. 측정할 때 모델 준비 상태,
해석·장소 조회·그래프·후보 탐색·집계를 분리하고 같은 데이터/문장 조건에서 비교합니다.

## 선택 저장

후보 선택은 기존 route-selections API를 사용합니다.
지원되는 지표만 학습하고 알 수 없는 필드의 방향을 임의 생성하지 않습니다.
브라우저의 제한된 재시도와 같은 선택 payload를 사용하며 마지막 사용자의 선택을 유지합니다.
