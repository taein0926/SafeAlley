# 교차로 회피와 육교 참조 연결

## 데이터와 적재

입력: `data_pipeline/raw/pedestrian_references/pedestrian_references.geojson`.
사용자가 제공한 미추홀구 선별 자료 350건(교차로 341, 육교 9)을 사용하며 외부에서 새로 수집하지 않는다.
원본은 Git 제외 상태를 유지한다. 각 점의 출처·기준일·원본 ID·`validation_status=unverified`를 보존한다.
입력은 WGS84 경위도, DB의 거리 계산은 EPSG:5179다.

```powershell
docker compose build backend frontend pipeline
docker compose up -d backend frontend
docker compose --profile tools run --rm pipeline load-pedestrian-references
```

Alembic `0012`는 별도 `pedestrian_references` 테이블을 추가한다. 로더는 ID 기준 upsert하고 기존 참조 행을 삭제하지 않는다.
도로의 `properties.pedestrian_reference`만 재계산하며 좌표, 연결 노드, 통행 방향, 안전도, CCTV, 계단 속성은 변경하지 않는다.
OSM 도로를 다시 적재했거나 참조 파일을 갱신한 경우 연결 명령을 다시 실행한다. 매 실행의 도로 메타데이터는 그 입력 파일의 참조 ID 집합에 한정된다.

교차로 대표점의 반경 35m 안에 있는 지상 도로 길이를 `intersection_exposure_m`로 기록한다.
겹치는 버퍼 및 동일 좌표는 공간 합집합으로 처리하므로 원본 중복 행 수만큼 비용이 증가하지 않는다.
OSM bridge/tunnel 또는 0이 아닌 layer 구간에는 교차로 주변 비용을 적용하지 않는다.
육교 참조는 60m 이내의 **이미 bridge로 태그된 footway/path/pedestrian/steps**에만 연결한다.
가까운 일반 도로를 육교로 바꾸거나 대표점 사이에 보행 연결을 만들지 않는다.

2026-09-22 로컬 연결 결과: 교차로 주변 도로 2,017개, 육교 도로 3개, 연결 육교 3건(도화동·제물포·주안동).
나머지 6개 육교도 DB에는 보존되지만 현재 OSM 연결 조건을 충족하지 않아 경로 육교 집계에 포함되지 않는다.
기존 OSM 15,694개 도로·계단 77구간의 좌표 및 기존 속성 해시가 연결 전후 동일함을 확인했다.

## 비용 및 우회 제한

- UI의 `교차로 회피` 0–100을 API `intersection_weight` 0–1로 변환한다. 기본값 0은 기존 경로를 유지한다.
- 지상 구간의 추가 비용은 `교차로 주변 길이(m) × 4 × intersection_weight`이다. 실제 금액이나 예상 대기 시간이 아닌 탐색용 비용이다.
- 육교에 음수 비용이나 강제 경유 보상을 주지 않는다. 교차로 주변 지상 구간과 비교해 상대적으로 선호될 수 있으며, `stairs_weight`와 기존 safety 비용은 계속 적용된다.
- 같은 route profile(최단/안전/균형) 및 계단 설정으로 교차로 가중치 0의 기준 경로를 먼저 계산한다.
- 추가 거리 상한은 `min(기준 거리 × 0.30, 300m)`이다. 안전도·계단 선택 자체가 만드는 우회까지 절대 최단거리 기준으로 제한하는 것은 아니다.
- 요청 가중치와 그 1/2, 1/4, 1/8로 탐색한 후보 중 거리 상한 내의 최선 비용 후보를 선택한다. 기준 경로는 항상 fallback으로 포함한다. 유한 후보 탐색이며 모든 거리 제약 경로의 전역 최적성을 보장하지 않는다.
- 교차로 회피가 켜졌을 때는 기존 balanced 후보의 대안 생성용 추가 비용을 끄므로 우회 상한의 기준을 부풀리지 않는다.
- 결과에 `intersection_baseline_distance_m`, `intersection_distance_limit_m`, `intersection_detour_limited`를 제공한다.
- 후보 순위에는 `intersection_distance_m` 최소화 조건도 전달한다. 데이터 미연결 시 지표를 0점으로 꾸미지 않고 미지원으로 보고한다.

`shortest`는 다른 회피 설정과 마찬가지로 **설정을 적용한 최단 프로필**이다. 교차로 회피를 켠 결과가 물리적 절대 최단경로라는 뜻은 아니다.

## 실제 API 비교

최단 프로필·계단 가중치 0, 거리 단위 m. 교차로 거리는 대표 좌표 주변 통과 길이이며 실제 횡단 횟수가 아니다.

| 경로 | 회피 0: 거리 / 교차로 주변 | 회피 100: 거리 / 교차로 주변 | 추가 거리 |
| --- | --- | --- | --- |
| 주안역 → 인천사랑병원 | 312.23 / 146.72 | 312.23 / 146.72 | 0 (먼 우회 제한) |
| 주안역 → 현대유비스병원 | 3,618.15 / 983.55 | 3,861.75 / 435.06 | 243.60 |
| 주안역 → 더나눔병원 | 3,445.68 / 401.06 | 3,710.14 / 0 | 264.46 |

연결된 육교 3개 모두 각 OSM 구간 양 끝점 간 API 경로에서 육교 1건으로 반환되는 것을 확인했다.
이는 실제 진입 동선·합법적 통행·현장 안전성·엘리베이터 운행의 검증이 아니다.

## 한계

지도는 `/api/pedestrian-bridges`에서 모든 육교 참조 점을 WGS84로 받아 한 번 로딩한다. 육교 아이콘은 OSM 경로망 연결 여부에 따라 청록색(연결)·황갈색(참조만)으로 구분한다. 클릭 시 이름·주소·원본 시설 정보·연결 여부를 표시한다. 점은 대표 위치이며 실제 진입점이나 엘리베이터 운행을 보장하지 않는다. 지도 이동마다 재조회하지 않는다.

교차로 점은 대표 좌표로, 다른 주소가 같은 좌표를 가리키는 항목도 있다. 현재 비용은 **근접도 선호**이며 공식 횡단보도 수나 교통사고 위험 추정이 아니다.
육교 9건 전체 사용, 무조건 육교 경유, 무장애 동선 또는 계단 없는 육교는 보장하지 않는다.
확인되지 않은 교차로/육교 연결은 현장 검수와 OSM 네트워크 보완 후 별도로 반영해야 한다.
기존 `major_road_fallback` 현장 검증 필터는 그대로 유지한다. 경사 관련 원본/API 필드는 삭제하지 않지만 UI 슬라이더는 교차로 회피로 대체한다.
